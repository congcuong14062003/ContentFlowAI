# Phase 08 — Campaign and calendar progress

Phase 08 was explicitly requested on 2026-11-05 and is in progress. It is not accepted as complete.

Applied additive migrations `20261105000800_campaign_calendar` and `20261105000801_campaign_calendar_tables`. PostgreSQL requires new enum values to commit before use in CHECK constraints; the original attempt was marked rolled back through Prisma, then the two files were applied. Ten migrations are now applied in total. No existing rows or applied migration files were removed. Prisma schema diff reports no difference.

Campaign API provides tenant-scoped list/search/status/brand filters with keyset pagination, create/detail/update with expected version, brand validation and content attachment. Campaign objective, audiences, status, UTC dates, brand, version and content progress are persisted. Content workflow transition policy includes IDEA, DRAFT, IN_REVIEW, APPROVED, REJECTED, SCHEDULED, PUBLISHED, FAILED and ARCHIVED. OWNER/ADMIN approval and rejection require backend role checks; rejection requires a reason. Scheduling accepts explicit UTC, requires approved/previously scheduled/failed state and increments Content.version. It does not mark content published. Manual PUBLISHED action requires SCHEDULED and records publishedAt/audit; stale concurrent version returns 409. Workspace timezone is stored as an IANA identifier and manager changes are validated.

Protected campaign list/detail forms connect to real APIs. Calendar UI offers Month/Week/Day/List range selection with workspace timezone display, an explicit UTC reschedule field and manual mark-published control. These are currently list layouts for each range, not full grid layouts. There is no auto-publishing adapter invocation; `SocialPublishingAdapter` is only a future port.
